# Fireflies Clone

A functional clone of the Fireflies.ai meeting-assistant platform — meetings library, interactive transcript viewer with click-to-seek, AI-generated summaries/action items/topics (mocked), and full CRUD for meetings and action items.


## Tech Stack

**Frontend:** Next.js 14 (App Router, TypeScript), Tailwind CSS
**Backend:** FastAPI (Python), SQLAlchemy ORM
**Database:** SQLite

---

## Architecture Overview

```
fireflies-clone/
├── backend/
│   ├── app/
│   │   ├── main.py        # FastAPI app + all API routes
│   │   ├── models.py      # SQLAlchemy models (schema)
│   │   ├── schemas.py     # Pydantic request/response schemas
│   │   └── database.py    # DB engine/session setup
│   ├── seed.py             # Populates DB with demo meetings
│   └── requirements.txt
└── frontend/
    ├── app/
    │   ├── page.tsx                  # Meetings library / dashboard
    │   └── meetings/[id]/page.tsx    # Meeting detail view
    ├── components/                    # Sidebar, TranscriptPanel, AudioPlayer, SidePanel, etc.
    └── lib/api.ts                     # Typed API client
```

The frontend is a client-rendered Next.js app that talks to the FastAPI backend over REST. There is no server-side auth; the app assumes a single default logged-in user, per the assignment's scope.

Real speech-to-text and AI summarization are out of scope per the assignment. Summaries, action items, and topics are seeded/mocked. The `POST /meetings` endpoint includes a lightweight transcript parser (`Speaker: text` per line) so new meetings can still be created realistically without a live transcription service. Swapping in a real LLM call is a contained change — it would slot into `create_meeting` in `main.py` where the mock summary is currently generated.

## Database Schema

| Table | Columns | Notes |
|---|---|---|
| `users` | id, name, email | Placeholder for the single default user |
| `meetings` | id, title, date, duration_sec, audio_url, created_at | Core meeting record |
| `participants` | id, meeting_id (FK), name | One row per participant per meeting |
| `transcript_segments` | id, meeting_id (FK), speaker, start_time, end_time, text | Ordered by start_time; drives the transcript panel |
| `summaries` | id, meeting_id (FK, unique), overview_text | One-to-one with meeting |
| `action_items` | id, meeting_id (FK), text, assignee, is_completed | Editable/checkable in the UI |
| `topics` | id, meeting_id (FK), label | Used for the "key topics" chips |

All child tables cascade-delete when their parent meeting is deleted.

## API Overview

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/meetings` | List meetings — supports `q` (title search), `participant`, `sort` |
| POST | `/meetings` | Create meeting (form fields or pasted transcript) |
| GET | `/meetings/{id}` | Full meeting detail (transcript, summary, action items, topics) |
| PATCH | `/meetings/{id}` | Update meeting metadata |
| DELETE | `/meetings/{id}` | Delete a meeting |
| GET | `/meetings/{id}/transcript/search?q=` | Search within one meeting's transcript |
| POST | `/meetings/{id}/action-items` | Add an action item |
| PATCH | `/meetings/{id}/action-items/{item_id}` | Edit or toggle-complete an action item |
| DELETE | `/meetings/{id}/action-items/{item_id}` | Delete an action item |

Full interactive docs are auto-generated by FastAPI at `/docs` once the backend is running.

## Setup Instructions

### Backend
```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python seed.py                   # seeds the DB with 4 demo meetings
uvicorn app.main:app --reload --port 8000
```
Backend runs at `http://localhost:8000`. Interactive API docs at `http://localhost:8000/docs`.

### Frontend
```bash
cd frontend
npm install
npm run dev
```
Frontend runs at `http://localhost:3000`. It expects the backend at `http://localhost:8000` by default — configurable via `frontend/.env.local`:
```
NEXT_PUBLIC_API_URL=http://localhost:8000
```

## Assumptions

- Single default logged-in user; no real authentication implemented (per assignment scope).
- Real audio files are optional. Without one, the media player renders a functional mock seek bar that stays fully synced with the transcript (click-to-seek works either way).
- AI summaries/action items/topics are seeded rather than generated live, per the assignment's allowance to mock this. The transcript-paste flow includes a basic speaker/line parser so the "create meeting" flow still feels real.
- Integrations, real-time meeting bots, team collaboration, and multi-user features are out of scope and shown as "Coming Soon" placeholders in the sidebar, per the assignment's mocked-sections list.
